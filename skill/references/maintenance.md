# 逻辑启动时的维护源与安装检查

用于每次开始一项协作，不是每个工具调用的前置。检查只读、有界，失败标未知，不阻塞其他独立安全工作；更新、安装、切入口和配置变更另需授权。

## 查本轮真实参与面

1. 从实际入口、软链目标、版本／包元数据与维护记录确定 call-cli 的源码、安装 payload、skill 副本及当前加载面。读取确切 source record；没有登记不代表没有上游，也不自动授权新增登记。
2. 对本轮参与的发起／执行 CLI，只查它们本次使用的协作 skill。相同 skill／共享后端去重；不用扫描整个技能库或所有设备。区分 CLI 版本、skill 版本、适配器版本及宿主 schema，不能互相替代。
3. 核对维护源：已知 Git 源可用 `git ls-remote VERIFIED_REMOTE HEAD` 与已读本地 revision 比较，或读官方发布／skill 子树；不 fetch／checkout／安装。新 program release 不一定改变 skill。不能查明来源或联网失败就记 unknown，不靠时间戳称最新。
4. 对所选传递 skill，按[技能传递](skill-passing.md)核查来源、固定 revision、相对资源／依赖、目标可读性；执行后另查实际读取与采用。传递成功不是采用成功。

留一份本任务简短记录：对象、维护源、安装／加载路径与版本、上游可用 revision、查询结果、必要本地适配、动作。值可为 unknown；有新版本不等于安全升级。可用更新、已部署与运行进程已加载分别报告。路径／哈希只证明对应观察，不证明业务通过。

同任务的 status／events／reply／intervene／close 复用这份记录，不重复全检或联网。若途中发现实际安装变化，在原有共享安装锁内核对本轮执行身份与兼容性；这不是重新查询 latest 或自动更新。新参与 CLI／新选 skill 只补该对象。

## ACPX 检查与维护边界

每个逻辑新任务记录执行设备 `acpx --version` 与 `npm view acpx version`；查询失败标未知，任务内已有持久记录可复用，不为展示重复调用。按实际公开命令、runtime API、事件与适配能力兼容，不把历史验收版本固定成上限。

正常派工仅检查，不运行安装。独立获准升级时先核安装渠道、fork／链接来源、无活动任务与版本影响，使用明确版本；不停止别人任务、不顺带更新其他 CLI、复制凭据或改默认 provider。升级后读回版本并做直接受影响回归与代表性真实短测；失败保留阶段，只回退本次获准动作，不重放结果不明的业务。设备离线保留历史证据并记本次不可达，不新增 cron、watchdog 或常驻更新器。
