# 验证范围与验收

本技能是操作指导，不认证当前机器、通知通道或所有角色组合。修改前读[核心需求](core-requirements.md)；每个结论绑定版本、入口、发起／执行角色、设备及谁观察，不能从测试数推完成比例。

## 分层证据

| 层 | 能证明 | 不能推出 |
| --- | --- | --- |
| 文本／结构 | frontmatter、链接、核心与边界保全 | 消费者实际发现、采用或运行时能力 |
| 原生加载 | 消费者发现并实际读 root／所需引用 | 原会话通知或持续协作成功 |
| 合成协议／假 worker | 指定控制、失败与结算条件 | 模型行为、平台投递或用户实际输入 |
| 真实模型／传输 | 所测工具、问答、取消续轮和产物 | 其他 CLI／设备或未测入口 |
| 真实发起端 | 自己消费阶段、回答、路由与核验改向 | 未观察的原生宿主投递／离线唤醒 |
| 原会话用户链 | 对应来源的输入、执行期回流与最终收到 | 所有 topic、重启恢复或通用稳定性 |

详细公开历史见检出目录的 VERIFICATION.md 或[仓库验证摘要](https://github.com/Loveacup/call-cli/blob/main/VERIFICATION.md)，按其版本和限定读，不把旧部署结果当当前安装。原始任务数据、身份与协议日志不随 skill 分发。Telegram 空通知问题需要逐事件真实宿主验证；提示词修改、合成派发或通用入口通过不能证明已修复或据此关闭 issue。

## 改动指导后的代表性场景

实际让消费 agent 读取候选正文／引用并作决策，观察其动作而非复述规则：

- 普通跨 CLI 请求能发现；普通本机命令不会误触发。原生 loader 的发现与模型主动选择分开记录。
- 逻辑启动只检查 call-cli、参与 CLI 的协作 skill 及本轮材料，installed／available／unknown 分开；status／同任务续轮不重复全检，失败不自动升级。
- 旧 schema 先核现有入口／桥；standalone 不冒称原生来源；缺 runtime 标签不推成全平台不可发起；OMP 同样核能力。
- 问题保留原 question_id；发起端自主动态调整与用户修订都路由到正确任务。pending／queued 不叫生效，unknown 不重放。
- steer／queue／cancel+resume 名义与实际一致；旧轮结算、目标 turn 接收和修订结果分开；迟到旧 runner 回执不覆盖新轮。
- Windows shell、远端 cwd、私有库存、批准策略和 skill 读取／采用边界保全。

这些是指导采用／行为场景，不称全链通过。链接、隐私和语义检查不能用 Markdown lint 替代，反过来也不能用模型回答代替实际控制证据。

## 真实链路最小验收

1. 读实际入口／版本／schema；用明确 DB connect/list 保存真实句柄，新建自有隔离任务。
2. 在执行结束前，原发起端消费公开阶段并汇报；对方提问后原发起端按编号回答，同 session 继续。
3. 发起端根据进展主动纠偏；再经其真实原生输入路径接收修订，由发起端调用控制并核验效果。测试驱动输入标模拟，脚本代答／代介入不算这一层通过。
4. 若测运行中介入，证明旧轮当时仍 running、随后真实 cancelled、同 record 新 turn 执行并体现修订；事后续轮不能冒充。控制探针窗口只证明受控情形，不保证任意工具／后台子进程立即终止。
5. 原发起端验收真实结果，close 并读回 no-session，核自有 watcher／材料清理。unknown、认证或模型失败保全成果，按精确句柄对账，不切模型或重放。

有界方案事先说明模型／effort、调用数、每轮期限、写入目录、停止与清理责任；不重演用户业务。分别记录源码、安装、加载、模型、发起端消费、实际改向与用户投递，未测保持未测。宿主自动唤醒、Telegram 多 topic、离开后的唤醒和重启恢复另验。
