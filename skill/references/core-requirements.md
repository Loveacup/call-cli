# 当前核心需求：持续双向协作

本文件是 call-cli 优化、升级、修复的唯一维护正本；个人安装保留语义一致的镜像，不另建需求版本。修改正文、适配或配套实现前先读本文件；用户改变需求时先更新这里，再同步摘要、引用、模板与验收。历史记录不是当前指令，能力目标不是已实现声明。

无论调用哪个 CLI，发起端都应持续掌握执行工作，将有价值的进展、问题、阻塞与最终结果送回真实的原会话；用户可随时在原会话补充或调整，由协调者传达到正确任务、确认实际生效并继续负责交付。用户不应切换终端搬运消息，或靠反复追问维持任务推进。这是本技能及配套实现优化、升级、修复的共同指向，不是某一 CLI 的特例，也不是当前所有链路已通过验收的声明。

- OMP、Codex、Pi 与 Hermes 可作为发起端；AGY 仅作为执行端，用户已取消其发起端需求，不再列为入口缺口或待验目标。发起、事件回流及控制分别适配各自宿主，绑定真实来源与精确任务，不把 Hermes 或任何 CLI 固化为必经中转。声明 runtime 名称不能替代宿主会话身份；不得把无原会话回流的 standalone 路径静默当作等价替代，入口不可达时说明缺口，不伪造来源或任务所有权。
- 区分事件产生、持久化、回注、协调者消费与用户实际收到；SQLite 保留全量公开事件供 `events(after=seq)` 游标读回，常规生命周期 `diagnostic`（非 `attention_required` 的常规阶段诊断）、`skill`、中间 `answer` 与连续相同 `stage` 在实时投递层降噪不刷屏，终态/待决策/`attention_required`/实质变化才推送。协调者转述有意义的阶段成果与待决策事项，不逐 token 汇报，也不只等最终结果。提问和介入结算后的必要续作由协调者承接。有长期责任方时，由该方直接创建并持有需跨轮的任务生命周期；短命代理需要发起时按实际宿主能力选择入口，事先明确持续协调与收尾路径，不假定父方自动继承所有权。暂不支持恢复不等于禁止该 CLI 发起。
- 用户可在原会话提出调整；发起 agent 也应根据执行期进展、偏差或阻塞，在已获授权范围内主动动态协调和调整，不依赖用户反复提醒。区分已提交、排队、被执行端接收及实际体现；按真实能力优先 steer，queue 与 cancel-and-resume 是不同语义，明确说明后备方式，不静默降级、不宣称无损。
- Hermes 作为 Alex 的副手，应理解真实需求并主动承担协调、纠偏、验收与收尾；已授权范围内的普通可逆工程选择自主推进与处理，不逐项重复请批；明显挤占主线或重大取舍必须带明确建议升级告知用户；新增生产副作用仍须按真实权限处理，审查发现本身不扩大生产操作授权。
- 按 CLI 原生能力、适配器、传输入口、协调层和宿主回流逐层核验；交互界面支持不证明所用 API 支持，OMP 亦须按同一标准验证。公共协作核心、发起端适配、执行端适配及工具链／skill 传递保持清晰职责与小接口，复用已有机制，仅隔离真实差异，不为各 CLI 组合新造调度体系。
- 新任务默认不设执行总截止；Hermes/OMP 模型工具不接收 timeout，保留 CLI/Python 显式硬 timeout 作为非常规兼容能力，不将其静默改为提醒。公共 runner 每 600s 至多请求一次发起方复核，持续活跃也不能无限推迟；`ReviewTracker` 严格区分最后可见输出时间 `last_visible`、最后实质进展时间 `last_substantive_at`、最后阶段 `last_stage` 与仅工具空转 `tool_churn_only`（静默与持续工具刷屏同样触发复核，且静默与活跃检查点共享冷却，不自动取消、关闭或续跑）。发起 agent 核查现状后选择继续等待、明确介入或取消，提醒不必逐条转给用户；入队不等于消费，CLI 依赖活跃 owner 轮询。已有硬预算在受支持续轮显式 clear_timeout 前仍生效；多问清除延迟到最后一答，中途介入替换答题序列时以介入自身 clear 选择为准，queued 拒绝清除。连接、启动与控制保持有界；unknown 保留资源占用并先对账，不自动重放。参数收口不是 shell 权限边界，时间限制不是费用保证。
- **停工未完成通报与协调者接续边界（未部署源码候选）**：共享 runner 与 OMP 适配只原样交付精确 task/turn 事实、降噪后的实质事件、600s 复核与注意事项（终态原样交回），不知道业务目标，也不依据可选 `group` 或已跟踪任务自动做项目级停工判定或生成伪小结。停工不是一种进程状态，进程退出（含 `completed`/exit 0）不等于业务完成；协调者在核实真实业务目标与接续事实后负责判断与行动——目标已独立验收则报验收完成、不误报停工，目标未验收且有授权下一步则在原权限内实际接续、不得因单轮退出停手。协调者须明确区分**单分支停**（某支已停但**同目标**仍有已确认活跃执行或已确认唤醒）、**等待有效执行**（仅指同目标存在已确认运行中的执行或已确认接续/唤醒）、**整体/全局停**与 **`unknown`**；**`unknown`、`queued`、空心跳、exit 0、未确认唤醒及同源无关活跃任务均不得作为接手续作证据**（含 `unknown` + `pending` 介入，须先对账精确 task/turn 与产物，禁止自动重放）。仅当协调者确认真实目标未验收、且无授权下一步接续也无同目标已确认活跃执行或唤醒时，才由协调者复用现有通知通道向原会话主动报**一次**『工作已停，未完成』简短小结，必含四要素：**已验**、**未完**、**停因**、**谁/什么条件能恢复**（含是否需用户动作）。不建常驻监工（no resident monitor daemon），不新增状态机、数据库或宿主 hook；仅在已有通道内尽力投递，不承诺进程或宿主异常终止后仍可送达。
- 一次逻辑协作启动时，检查 call-cli 本身及本轮实际参与的 CLI 协作 skill 的维护源与安装现态；按需核查本轮所选传递 skill 的来源、版本、目标端可用性与实际采用。区分可用更新与已部署版本、查询失败与已是最新；不扫描所有 skill、不在状态查询或同任务续轮重复检查，不因发现更新而擅自覆盖本地适配、打断任务或更改配置。
- 验收贯穿真实链路：执行中进度回原会话 → 用户在原会话补充 → 正确目标收到并按新要求继续 → 问题／失败／结果回到原会话 → 验收与收尾。模拟输入、离线测试、通用入口、宿主原生入口与真实用户投递分别记录，局部成功不代替全链通过。

实现与验收按来源、执行期回流、人工及主动调整、接收与生效、持续续办、最终清理逐项定位证据。分别标明源码实现、安装部署、当前入口加载、真实执行及用户投递；不能用其中一项代替另一项。离开当前协作后的离线自动唤醒、重启恢复与接管手动会话仍是独立范围，不因此削减在线协作目标。

### 控制动作与协调责任

- 自动观察仅由原 native owner 串行 `session/load`，不产生 prompt，也不定时 nudge。源码候选 `dialogue` 仅用于有真实 launch/turn/epoch 输入能力的活跃 AGY native owner，在完整 load 与下一请求之间串行 prompt；前台未返回仅排队，不是 active-tool 热 steer。旧 owner 无通道明确 unsupported，不把 `intervene` 静默改义。候选 schema 不代表运行 gateway 已加载。
- OMP 等既有 `intervene` 保持 cancel+resume：稳定 command_id 绑定原轮；`list`/`status`/`events`/`recovery_status` 均为纯只读（`?mode=ro` + `PRAGMA query_only=ON`，无建库/schema/chmod/写锁/持久 `bind`/推进/拉起，亦不新建、激活、停止或修改 `wait` 轮询跟踪；保留显式 `start`/控制动作开启的既有 `wait` 轮询），确认取消结算后由原 controller 以同一 `command_id` 显式重试 `intervene`（通用入口另可通过 `wait`）推进一次 successor；unknown/HOLD 不续派。pending、RPC 返回、原生 dispatch、coordinator 报告采用、独立产物读回分别取证。
- `task.turn` 标识执行／续办轮；AGY 同运行轮显式输入以单调 `interaction_seq` 区分，旧 interaction envelope 不得结算新输入。roster 属于当前 native session，输入间保留；完成后 successor 才换 turn。dialogue 必须携带 expected_turn 与稳定 command_id，问题回答另绑 question_id，发送开始后不明保 unknown、不自动重放；不为旧进程补造能力。
- 机器唤醒须读取精确 task/turn/seq、问题及命令并作判断；重复 `[SILENT]` 不是消费或行动。仅已消费且无新增义务的机器回合可按宿主协议精确静默；真人、queued/steer/OOB 或来源不明必须实质回应。无合法输入／恢复通道时报告能力缺口并保留责任，不以显示修复冒称 worker 已推进。
- OMP 执行端仅 stage、无最终答案的轮次保持 unknown/HOLD；与 AGY 共用已持久 task/turn/seq 的 attention_required/notification_scope、可行动 next_action 和原 runner stdout 通知，不把阶段当完成。OMP 发起适配复用原轮询/followUp；无新终态事件时按 task snapshot 补提醒，同轮 snapshot/终态去重，新 turn 重新提醒。无自动重放或介入。生成、排队、真实宿主消费和用户收到仍分层验收；本合同不修复宿主混真人静默或 SJ/Jev producer。
- unknown snapshot fallback 只由该 task 当前 turn 的 unknown 事件替代；旧 turn 迟到事件不能挡住新 turn 提醒。提醒记账取实际发送的 unknown turn，不依赖同包 task snapshot 已是 unknown；无 turn 旧事件按当前 task turn 兼容，不能据此恢复未知的历史归属。非 unknown 事件顺序与游标消费不变。
- 当前 task track 在内存保留实际已送入 followUp 的 unknown turn 集合，不只记最高 turn：已提醒旧轮迟到不重复，从未提醒过的旧轮仍须首次送达。集合随原 close/detach 生命周期清理，不新增持久去重服务，不承诺宿主重启后的 exactly-once。
- **本版本源码；安装后需宿主重载 schema 与新 runner 后生效**：`dialogue` 与已结算 `reply` 新增显式 `question_ids: list[str]`，与标量 `question_id: str` 严格互斥（不得同时传入；`question_id=None` 与单值 `question_id` 保持兼容；拒绝空数组、空字符串、非字符串元素、重复 ID、CSV 逗号字符串与标量联合类型强转；禁止 trim 或修改 ID 字节；按原始字节精确匹配当前轮未答问题，且仅在 `command_id` 幂等意图比对时使用 `sorted(question_ids)` 规范化顺序；不引入事后零发送补结算子协议）。`dialogue` 另新增可选整数 `blocker_interaction_seq: int`（仅限 `dialogue` 动作，要求 `type(v) is int and v >= 0`，拒绝 `bool`、负数及非整数，`0` 按 `is not None` 处理），与 `question_id`、`question_ids` 及 `withdraw=True` 严格互斥；未传入时单题、多题与普通未绑 `CALLCLI_DIALOGUE` 头保持不变，零新账本。仅在首次受理时核验 `native_observation.question_blockers` 中存在匹配 `interaction_seq == blocker_interaction_seq` 且 `reason == 'incomplete_question'` 的活跃 blocker 及同轮单占互斥（`accepted` 阶段 `withdraw` 或 `target_command_id` 替换释放占用），同 `(command_id, intent)` 重试校验先于活跃 blocker 与 `running` 校验以保持已结算命令幂等；`reply` 不接受 `blocker_interaction_seq`。
- 多题 `dialogue` 仅发送单次 `session/prompt`，且仅在 `returned` 时原子记录 `answers[qid]=prompt` 并移除全部绑定问题；`accepted`、`claimed`、`send_started`、`withdrawn`、`superseded`、`not_sent`、`cancelled` 与 `unknown` 均不清除问题，处于 `accepted` 时 `withdraw` 或 `target_command_id` 替换释放全部绑定 ID。
- `reply` 共享同一 `question_id` XOR `question_ids` 校验、原始字节匹配与排序集合 `command_id` 幂等逻辑，同时保留既有合并正文行为（总回答数为 1 时取 `answers[0][1]`，多题时按 `'\n'.join(k + ': ' + v ...)` 拼接）。

### 事件分流、实质进展汇报与 600s 复核（未部署源码候选）

- **未部署源码候选边界**：本节为隔离候选仓的规则同步与需求镜像，不代表主仓已合入或现役 `current`/宿主插件已部署生效。
- **事件与实质进展驱动汇报（禁止定时刷屏）**：面向用户的通知仅由真实事件与实质进展驱动（产物、已验证结论、阻塞、待答问题、需改向风险、带明确建议的重大取舍），绝不按固定时间间隔发进度消息。Slice A **本版本源码**在保持 `Store.events` SQLite 100% 原始落库的同时，通过 `events.classify_event_delivery`（含 `ROUTINE_DIAGNOSTIC_REASONS`）在 `runner.py:publish()` 实时 stdout 与 `omp-extension.mjs` 投递面过滤常规生命周期面包屑、中间流式 `answer` 行及连续重复非 `quiet_notice` `stage`（同时放行异常 `diagnostic`、`question`、`permission`、终态与 `quiet_notice`）。
- **自主纠偏 vs 带建议升级**：已获授权范围内的常规可逆工程选择由协调者自主处理，不逐项打断用户；明显挤占主线、超出既定边界或涉及重大取舍的变更必须附明确推荐方案升级用户。
- **600s `quiet_notice` 复核协议**：Slice A **本版本源码**以共享 `events.ReviewTracker`（冷却 `600s`，三端共用）生成 `quiet_notice=True` 复核帧与脱敏 `review_facts`（含 `progress_state`：`substantive_progress` / `tool_churn_only` / `quiet`，以及 `substantive_count_since_review`、`tool_count_since_review`、`failed_tool_count_since_review`、`substantive_idle_seconds`、`last_stage`）。到点唤醒后，协调者**必须**核查精确 `task/turn/seq`、`review_facts.progress_state`（显式识破工具很忙但零实质进展的 `tool_churn_only`）与实际磁盘产物，再明确作出“继续等待 / 自主可逆纠偏或介入 / 带建议升级用户”之一；严禁因超时提醒自动取消、关闭或续跑；Hermes 机器通知轮仅在确认事件已消费且无任何新增交付、待答、阻塞或协调义务后才精确回复 `[SILENT]`。

## Hermes 透明 Git/worktree 管理（未部署源码候选）

- **轻量、零守护进程、由协调者自然判断（未部署源码候选）**：纯标准库薄辅助 `git_worktree.py`（无 daemon、不写 SQLite、不修改 `bridge.py` 写锁语义及 `call_cli`/`call_cli_omp` 工具 Schema）仅封装重复且易错的 Git 动作，不在代码中另造“策略选择状态机”。是否使用 Git/worktree 由协调者（Hermes）依据任务自然选择，**不强制所有任务 Git 化、也不每次询问用户开关**，并保持正常成功链路最短：
  1. **普通目录**：非 Git 目录的轻读写或单线任务直接推进并验收，不强行建仓；仅在确需隔离或回溯且位于授权任务目录（拒绝 `/`、`$HOME` 及宿主系统根目录）时按需 `init-repo`。
  2. **单仓直接推进**：既有单仓内的单写者常规任务直接在该仓推进，保护用户既有未提交改动，不额外建 worktree。
  3. **并行／写隔离 Worktree**：需并行写者或隔离实验时，由协调者在派工前准备**仓外同级** worktree，启动即明确收敛目标（`target_dir`/`target_branch`），并在授权范围内承担完整收束，不把合并甩给用户。
- **仓外同级 Worktree 与 Fail-Closed 边界**：`bridge.py:_check_writers` 按规范化路径相等与父子前缀重叠做写锁互斥，仓内 `.agents/worktrees/*` 会与仓根互锁；隔离时统一使用**仓外同级目录**，保留 `relative_subdir` → 有效 `cwd`。worktree **只隔离已检出文件**，不是权限沙箱，也不继承主仓未提交脏文件或未跟踪文件。一旦请求隔离、建树、路径校验（如指向仓内／仓根／仓父目录或非法相对路径）或复用分支归属校验失败，**立即 fail-closed 停工报错**，严禁静默回退原工作区；返工或续作在确认前序停写后串行复用同一检出。
- **透明告知与简洁汇报**：向用户与执行方简要透明写明 **“Git/worktree 由 Hermes 管理”**、分支／实际检出目录（`worktree_root` 与有效 `cwd`）、`device`、检出读回基线 `base_commit` 与收敛目标；不把逐项事实字段清单或全 worker 停机证明当正常成功链路的硬门槛。
- **收束闭环（收获 → 保护用户改动 → 串行整合 → 目标复验 → 默认清理或明因保留）**：
  - **收齐成果（`harvest`）**：先收集分支已提交及未提交／未跟踪交付（自动过滤 `__pycache__`/`.pytest_cache`/`.DS_Store`/`*.pyc`/`*.pyo` 等未跟踪噪声，按需校验 `allowed_paths`），禁止对主工作区执行 harvest。
  - **保护目标用户改动与冲突现场**：串行 `git merge --no-ff` 前检查目标仓 `MERGE_HEAD`、暂存区（staged）改动及与传入文件重叠的未提交／未跟踪改动，存在即停手并保留工作树（`disposition='retained_with_reason'`）；**严禁自动 `git stash`、`git reset`、`git clean`、`git worktree remove --force`/`-f` 或 `git branch -D`**，无重叠的非冲突用户改动原样保留。**遇真合并冲突时保留完整冲突现场与 worktree，绝不先机械执行 `git merge --abort`**（dirty merge 无法保证安全回滚），而是列明冲突文件并带建议升级用户。
  - **四态交付严格区分与默认清理**：交付核对仍区分**分支提交（`branch_commits`）／未提交改动（`uncommitted_files`）／已集成（`integrated`）／已验证（`verified`）**，不在目标目录独立复验前以 commit 或合入推定 `verified`。当且仅当已整合、已复验（`verified=True`）、无活跃 writer 且工作区干净时，默认执行非强删清理（`git worktree remove` + `git branch -d`，`disposition='cleaned'`）；其余情况保留并明确返回 `disposition='retained_with_reason'` 与非空 `retain_reasons`（替代默认长期留存）。主仓合入、现役 `current` 部署与对外 `push` 仍须独立授权。
- **薄辅助 CLI（未部署源码候选）**：`git_worktree.py` 提供 `init-repo` / `prepare` / `inspect` / `harvest` / `converge` / `check-cleanup` / `cleanup` 单行 JSON 子命令。


## AGY 原生模式与薄桥边界

单代理、Swarm、Teamwork、Dynamic 均保留。Call-CLI 只负责原来源收发、必要进度与问题、修改／取消转达、公开结果和自身会话收尾；AGY 原生负责模式内部角色、工作分配、审批策略、权限和执行编排。业务范围由发起者授权，不改写为父写／子只读或固定内部分工，不强制内部审批 mode，也不以子写权限证明作为接入或完成门槛。默认 OCS 不因任务内容静默改变；源码接入、离线验证、实装和用户闭环分别报告。

新 AGY 任务未指定模型默认 `ocs`。`oc/oa/4c/4a/4h` 为现有模型简称，裸简称走单代理；后缀 `s` 走原生 Swarm，`t` 走原生 Teamwork，均通过实际 advertised slash command 发起，不降级成普通 prompt。显式 `agy_mode=single/swarm/teamwork/dynamic` 与简称意图必须一致。完整 advertised model ID 与显式 effort 保留既有选择／读回；所有入口仍共用 prepare_start，不回填旧记录。worker 型号仅在用户显式指定时作为原生任务偏好转达，不再默认钉住逐成员型号或作为完成门槛。

当前片在保留 Swarm 薄桥及所有既有成果的基础上接通 Teamwork 最小纵向路径：按 advertised teamwork 命令启动，同 owner 完整 load、异步访谈、原来源答复／修改、公开最终结果和 mode=teamwork receipt／正常 close。invoke_subagent completed 仅证明委派返回，不是整个业务完成；优先沿用 CALLCLI_STAGE/QUESTION 和已知公开原生工具阶段，不建立逐角色账本、全后代终态证明或固定人工确认门槛。公开问题／审批事件有则沿现有机制传递；无事件明确不可观测，不推测内部审批状态或强塞回调。保留现有公开回调的会话身份校验，不修改 AGY 权限、配置或内部调度。启动问答与完整业务支持分别取证，不以换前缀冒称全链通过。取消仅沿原有单次 native cancel，未知如实、不重放／强杀，不定义模式永久必须 HOLD。

简称解析采用有限保留语法，不猜任意前缀：已定义小写简称照常解析；大小写变体、重复／混合 `s/t`、多个简称直接拼接或经空格／`,`／`_`／`:`／`/`／`+`／`-` 组合，以及简称后误附 `-low/-medium/-high` 均拒绝。该保留语法内的字符串不兼作不透明完整 ID；其他非空 literal ID（如 `octopus-exact`、`oc-special`）原样交给现有 advertised catalog 校验，不按 `oc/oa/4a` 前缀拒绝，也不保证未广告 ID 可执行。未指定的自然语言拼法不作无限猜测；模式仍须用已定义简称或显式参数表达。

- 授权与执行免阻策略（2026-11-15 新需求覆盖旧 `approve-reads` 默认合同）：所有经 Call-CLI **新启动**的 `OMP`、`Codex`、`Pi`、`AGY` 默认以原生方式跳过交互审批、执行 CLI 沙箱与 CLI 目录限制（`execution_policy=native-skip`，不仅父级 ACPX `--approve-all`）：
  - `OMP`：POSIX 传 `--agent 'omp acp --auto-approve --allow-home'`（配合 `--approve-all --non-interactive-permissions deny`）；Windows 通过 `acpx/runtime`（`SharedAcpRuntime` + `createAgentRegistry({overrides})` + `createFileSessionStore`）传入结构化 `agentArgv=['omp', 'acp', '--auto-approve', '--allow-home']`，不改全局配置、跳过原生工具审批与 `~/` 目录保护。
  - `Codex`：`INITIAL_AGENT_MODE=agent-full-access` 并在创建会话后执行 `acpx codex set-mode -s <session> agent-full-access`（ACP + `--approve-all --non-interactive-permissions deny`）；跳过审批与 CLI 沙箱/目录限制。
  - `Pi`：ACPX `permissionMode=approve-all` + `--approve-all --non-interactive-permissions deny`（`pi-acp` 在进程内无 CLI 沙箱或目录拦截开关）。
  - `AGY`：默认 `agy_approval=skip-permissions`，POSIX ACPX 与 `NativeOwner` 共用 `agy acp --dangerously-skip-permissions`（父 fallback `approve-all`），Windows ACPX `off` 通过 `acpx/runtime` 结构化 `agentArgv=['agy', 'acp', '--dangerously-skip-permissions']`；保留显式 `approve-all` / `approve-reads` 兼容。
  - **Open Empirical Upstream Gap (ACPX Shared Runtime `fs/*`)**：实证 ACPX `0.22.0` / `0.21.1` Shared Runtime 中，`FileSystemHandlers.resolvePathWithinRoot` 硬性将 `fs/read_text_file` / `fs/write_text_file` 限制在 `cwd` 子树内（越界返回 `-32603`），`approve-all`/`full-access` 对此无效，且 `createSharedAcpRuntime({ fs })` 抛出 `ACP_INVALID_RUNTIME_OPTION`（`"fs belongs to the in-process runtime and is not supported by shared sessions."`），公开 `acpx/runtime` SDK 无 `allowedRoots`/`fsRoot`/自定义 `fs` 回调选项。这属于待 PM/用户决策的实证上游目标缺口，不是已接受用户例外：**Option A** 保留现有 Shared Runtime 架构并将 `fs/*` 限 `cwd` 列为明确上游限制（跨目录读写依赖各 CLI 原生文件工具，已知仅回调型路径会报 `unavailable`）；**Option B** 作为独立后续阶段推动上游新增受支持根目录/FS 选项，或替换/退回 in-process 直接 ACP 适配（代价为重做 Shared Runtime 队列与多进程会管）。
  - **边界不变**：仅对新启动生效，不打断、不静默升级既有运行中或历史任务（缺 `execution_policy` 仍按既有合同）；不改任何 CLI 全局用户配置（`~/.acpx`、`~/.codex`、`~/.omp`、`~/.pi`、`~/.gemini`）、上游包、凭据或其他 profile；业务任务范围、origin/task/controller 身份隔离与 `write` 单 writer 互斥保持严格执行（`write: false` 只读并发任务在 `native-skip` 下同样不抢写锁，但仍应遵守任务范围）。源码候选在受支持部署/reload 前不对运行中宿主或当前会话生效。

### Dynamic 源码接入候选

显式 `agy_mode=dynamic` 选择同一 native ACP owner 与 `/run-workflow`，没有新增简称；`single/swarm` 为共享模式字段的既有两种语义。省略模式保持既有默认及旧记录行为，`agy_swarm` 路由冲突拒绝。Dynamic 模型使用完整 advertised ID/family，子 agent 的 inherit/flash_lite/flash/pro 属于原生 `run_workflow` 命名空间，不复用 `agy_worker_model`，不把父配置说成子模型已证。缺 `run-workflow` 广告在业务 prompt 前拒绝，无普通 prompt/Swarm fallback。

在默认 `native-skip`（`agy_approval=skip-permissions`）下，AGY Dynamic 经 `agy acp --dangerously-skip-permissions` 原生执行 `/run-workflow`：不再要求每条脚本停在 Call-CLI 人工 `permission` 审批门槛（避免与原生 skip 冲突）；若意外收到同源 `run_workflow` 权限请求且存在无歧义允许选项，检验 Script 合法性后直接按 skip 策略放行；异源/子 session 仍拒绝并 HOLD。**真实 Script 身份观测与人工审批严格分离**：无论是否 `native-skip`，均必须实际观察到合法、非空、非 `ScriptPath` 且不超 `128000` UTF-8 字节的绑定 `Script` 身份（`workflow_script_sha256` 匹配 `owner.workflow_identity[toolCallId]`）；未建立真实 `Script` 身份前的 `tool_call_update`、缺失/空/仅 `ScriptPath` 的终态一律拒绝或阻塞，绝不结算 `completed` 或卸载（保持 `unknown`/HOLD），仅在同 `toolCallId` 已建立合法 `Script` 身份后允许稀疏 `tool_call_update`（省略/空 `rawInput`）。仅当显式选择 `agy_approval=approve-all|approve-reads`（或历史非 skip 任务）时，仍走以下精确单次脚本审批协议：原 controller 通过 `permission` 对精确 `permission_id`、`expected_turn`、稳定 `command_id`、Script SHA-256 作 `allow_once/reject_once`（上限 128000 UTF-8 字节，同时存在 `args.Script` 时须与 `rawInput.Script` 一致，不接受歧义选项）。

原始workflow事件在normalize之前核对args.Script与rawInput.Script、继承同ID的workflow身份核验稀疏update；原始重复tool_call不等价合法tool_call_update，单次回放/执行响应中重复创建保HOLD，不以snapshot合并证明single-use。pending/decided/send_started/unknown许可阻止seal，封口后不再接纳或发送新批准；卸载期间新增许可拒绝、新执行/正文使旧快照失效并保unknown/HOLD。通信RPC deadline不计精确审批中的原来源决策等待，发送/接收与实际通信仍有界，不引入任务总截止。

仅对已识别workflow的原始args/rawInput：字段缺省、空对象或同Script对象可保留既有身份；显式null、字符串、数组、数字、布尔及非字符串Script无法证明同一性，保守unknown/HOLD。现有真实ACP样本未证明null是“无变化”信号；此局部证据合同不是全局ACP类型判断，不推断恶意或断言不同脚本实际执行。普通工具不套用此workflow guard。

命令广告可晚于load response；缺广告时在原读取loop中最多观察1s异步通知，见精确run-workflow即返回，无新RPC/业务prompt；到界仍未广告才拒绝。最终工具终态且前台已end_turn、无未决问题时，replay无换行父答案以该边界finish，先确认可用输出再seal/unload；半行问题仍HOLD。其他父工具failed不一律否定workflow completed：失败之后有新的父最终答案才按恢复性失败处理，completed仅代表该父结果合同，不代表所有工具成功。末尾失败后无新答案保留上下文/HOLD；workflow自身failed仍非业务成功。

Dynamic可信mode receipt提交时同步native_phase：正常completed为settled，失败unknown为unknown；不把dynamic_pending留在已结算任务上。该显示修正仅作用于新receipt提交，不改写历史任务或放宽实际完成／close证明。

公开进展仅为父工具安全ID/name/status、父公开文本、问题与许可；当前ACP样本无直接Logs/Output/phase/子agent事件，native_observation明确unavailable，父回答不升级为子结果独立证明。首end_turn后完整load持续对账；正常完成须run_workflow completed、对应已批准脚本hash、父工具无活动项、父公开最终答案及精确卸载/负向读回；业务验收仍由发起者独立完成。失败工具可在相同安全终态卸载并留可信mode receipt，但任务仍unknown，不报业务成功。close只消费原owner的精确mode receipt，不借Swarm roster/add/kill。

显式dialogue是同turn排队输入，前台返回后串行发送，不承诺运行中脚本/child热修改；问题回答绑定原question_id（**本版本源码**：或显式 `question_ids`，在 `CALLCLI_DIALOGUE` 转发 `question_ids` 与完整 `questions` 原题元数据，同时保持单题与普通未绑头逐字节一致；仅在 `returned` 时清除所绑问题并写入 `answers`，其余或新到正式问题仍阻塞）与interaction，而 Dynamic 未完半行问题片段直接对账并保留 `unknown`/HOLD、不暴露 `incomplete_question` blocker，且遇 `blocker_interaction_seq` 时显式拒绝（发送前失败并保留 HOLD），绝不静默丢弃该字段并结算。半行问题归属不明、历史变更、fatal、断连、缺审批/脚本hash/工具证据、取消传播未证均unknown/HOLD，不自动续派。取消不产生Swarm cleanup prompt，不把session/cancel、stdio退出或卸载当所有后代已停；无持续恢复owner保证。Dynamic真实call-cli宿主/用户闭环和取消级联仍待单独授权验收；Teamwork最小源码路径见前述薄桥边界，不以Dynamic样本冒称支持。

Teamwork修正真实样本已证明brief采用revised，但原生材料报告implementer/reviewer交互许可60s超时，父ACP未收到子许可，终态non-victory且预期结果缺失；不是父方明确拒绝，也非子agent逐个终止证明。保留本轮整体目标，当前不假称完整支持，不自动重跑真实样本或绕审批。


AGY 原生模式复用同一 native ACP owner、Store/runner、身份和写面互斥，不创建第二 controller 或调度器。end_turn 是前台返回；随后完整 load 对账公开历史，工具仍活动或问题待答就继续持有 owner。当前响应有最终回答且公开工具已终态时可正常回收结果，不推断未公开内部工作已结束。仅发布完整成功回放的增量，丢弃 thought，历史歧义如实 unknown，不静默重写。

Incomplete public question fragments are not formal questions. Preserve their generating interaction across explicit inputs; expose only sanitized blocker reason, interaction and available actions through existing observation/events. A tracked original history slot may resume by prefix growth and a provable boundary, after the full replay validates, publishing once under its original interaction. Replays must not duplicate it or merge identical text from another interaction. Ambiguous ownership/history stays actionable unknown/HOLD, never silent permanent waiting or guessed recovery; no arbitrary history-rewrite algorithm. Question-bound dialogue (`question_id` or `question_ids`) settles only its explicitly named formal question token(s) and never supersedes an `incomplete_question` blocker, nor may an ordinary unbound dialogue (whether in the same interaction or a later interaction, even when formal questions are empty plus a final public response) automatically clear any `incomplete_question` fragment. Under the explicit blocker-supersede contract, superseding a non-growing `incomplete_question` fragment requires a `dialogue` command with explicit `blocker_interaction_seq: int` (`>= 0`, `bool` rejected, `0` handled via `is not None`, mutually exclusive with `question_id`/`question_ids`/`withdraw`) matching an active `incomplete_question` blocker: only the targeted `interaction_seq` slot is cleared (leaving any other fragments blocking), prefix-growth formal question recovery still takes precedence and unanswered/new formal questions remain blocking, no synthetic `answers` entry is written, and settlement occurs only after `command.status == 'returned'`, unchanged original slot text, exact `dialogue_body` replay in `history[d_index+1:]`, no active tools, empty `questions`, and a usable final public response (`accepted`/`claimed`/`send_started`/`withdrawn`/`superseded`/`not_sent`/`cancelled`/`unknown` never clear).


Swarm／Teamwork 复用原 owner 的公开前台响应、完整 load、工具状态、问题与最终回答判断当前请求是否结算，业务产物由发起者验收；不要求 CALLCLI_RESULT、逐成员 add/kill/model 或全员终态才能回收结果。首 end_turn 仅在无公开活动工具、有最终回答且无待答问题时可结算当前请求，不等同证明整个原生项目或全部后代停止。正常 close 记录本任务会话卸载与可观察状态；缺内部细节如实标 unknown，不把它自动升级成业务失败或伪造停写证明。取消仅转达原生控制、不重放业务或自动生成逐员清理 prompt；原生未给停止确认时明确报告，不宣称全后代停止。旧任务已有 receipt-only/HOLD 记录不追溯改写。

现有取消、身份隔离、写面互斥和未知效果不重放原则保持。旧版 Swarm 逐成员清理证明只解释历史 receipt，不作为新薄桥模式的必经工作流；新模式只陈述实际观察到的前台取消、会话卸载和未知内部工作状态，不人工补证、盲 attach 或强放旧 HOLD。


Native close/reconcile consumes an existing trusted owner receipt only: no second owner, post-unload load, repeated close or ACPX substitution. Model-provided or task-JSON cleanup fields alone are not trusted receipt provenance (in the published source **本版本源码；不自动释放既有任务锁**, ended-owner native receipt settlement requires a bound durable record in `native_cleanup_receipts` and inactive `runner_pid`, while legacy `completed` task-JSON cleanup and `never-created` remain same-principal only; see `## Ended-owner native access`). Fresh exclusively created, empty pre-submission history with proven no prompt and exact unload may release an abnormal preprompt failure while preserving its original diagnosis; reused/creation-uncertain sessions require evidence and otherwise HOLD. Permission diagnostics expose only safe callback identity/scope/kind/options/decision/send outcome; missing allow_once is explicit, child scope is not authorized, approve-all never silently becomes skip-permissions.


新 Swarm 不再要求模型生成 turn/worker envelope；结果归属由原 owner 的 task/turn/launch/epoch、完整回放与精确 dialogue 用户消息边界确定。旧 envelope 兼容/逐成员证明仅为历史记录，不用于新响应结算，也不授权追溯释放旧任务。

AGY abnormal exit/fatal output and OMP unknown settlement must produce durable, task/turn-bound actionable notification through the existing runner/native return paths. OMP polling/follow-up and Hermes notification are not proof of real host consumption or user delivery. The AGY 1.5.8 v3 candidate sample verified one G4C low coordinator and one G4H medium worker with approve-reads: after end_turn, one public cancel triggered original-owner cleanup, completed kill plus status, exact unload/not-found, a trusted cancelled receipt, equal repeated public close and natural exit 0. This is a direct candidate control-path observation using a threaded launcher/observation wrapper, not default-launcher/deployed-host acceptance, active-tool hot cancellation or arbitrary descendant termination. Earlier unknown/HOLD samples remain unchanged; no reconciliation or retroactive settlement was performed. Further paid samples, production DB/policy changes, old-task controls, upstream edits, installs/reloads/deployment and external writes require their own explicit scope. Keep prior failures and source-bound test counts historical; see the [current verification index](../../VERIFICATION.md#current-acceptance-index).

## Ended-owner native access

Prefer preventing orphaned tasks; when they occur, make diagnosis and recovery available through the existing native interface. A current session in the same trusted profile and original route may discover and inspect tasks whose original owner is currently ended according to committed read-only host metadata. Explicit close reasons are distinct from compression, reset, disconnect, missing PID or mere task completion. In **本版本源码；不自动释放既有任务锁**, when a task originates after a session reset and later undergoes rotation compression, only that task's own origin ancestor node may carry a text `_reset_from` marker; descendant hops still require consistent native source and committed compression metadata without reset/branch/delegate/compressed markers, ancestry beyond the origin node retains bounded 32-edge cycle detection only, and pre-reset tasks remain inaccessible. No model-provided identity or parent/child relation grants access.

Inspection must not advance pending interventions or launch business work. Explicit settled continuation binds the observed turn and stable command ID; admission atomically records a single current controller and monotonically increasing control_epoch while preserving Origin/history. The admitted controller retains control after the former owner reopens; former owners may inspect but cannot control a live successor. Runner dispatch binds exact turn/launch_id/epoch and never reads a newer successor from delayed argv. Missing controller fields on old tasks mean original Origin/epoch 1; legacy unbound runner compatibility is limited to an unclaimed first turn, never a successor. New-controller active cancellation remains available; unknown/HOLD is never replayed.

Native local exact-record close/reconcile reuses the P2 durable fence. Recovery requires explicit observed turn and current-controller or trusted ended-controller admission, a settled/unknown snapshot, writer exclusion and exact backend binding; stale former-controller inspection is not recovery authority. Backend reconcile performs no close, and only exact closed record plus scoped no-session may settle HOLD transactionally. Existing uncertain close attempts are never repeated; receipt preserves attempts and sanitized stage/reason_code. DB fence does not prove arbitrary detached processes stopped. Start/query/event/settlement receipts provide a recovery card and honestly mark missing verified handoff/pre-exit coverage; short-lived agents remain supported. Source validation is not deployment or live-host acceptance. **本版本源码；不自动释放既有任务锁**：`agy_swarm == 'native'` 的 `close`/`reconcile(expected_turn)` 在同可信 profile 与原 route 且旧 owner 已结束、无活跃 `runner_pid` 时，在事务内按基础路由/controller 归属核验并结算已绑定、已卸载的 `native_cleanup_receipts` 持久回执（`native-mode-settled`、`verified-cancellation`、`fresh-no-prompt`），不转移 `controller`/`control_epoch`、不打开输入通道、不启动或 `session/load` native 会话，也不放宽活跃控制门槛；legacy `completed` 任务 JSON 清理（`native-add-kill-completed-and-session-unload`）与 `never-created` 仍仅限同 principal。关闭、对账或释放已结算（`completed`/`cancelled`）旧任务时，若同写面存在合法冲突的后继 writer，则先标记旧任务 `resource_state='superseded'`（写互斥跳过 `released`/`superseded`）并在确认 `closed` 时移除；失败保留 `superseded` 以免误阻后继，无后继孤立失败仍 HOLD，活跃/`unknown` writer 仍保持排他互斥。

普通 close/reconcile 的原有权限与证明门槛不变：unknown 默认仅 probe，缺 exact record、远端或证明不足仍 HOLD；不得重放不确定的外部 close 或业务。Hermes 的 ended-controller 业务续办仍独立受原身份及路由规则约束，不因资源释放获得控制权。

### 写占用恢复合同

`resource_state` 与业务状态独立。真实活跃 writer 必须互斥：queued/running/cancelling 或 runner 仍存活时拒绝释放。AGY native 的准备失败仅在 fresh 独占创建、空历史、已证无 prompt、精确 unload 且 owner 已退出全部成立时自动围栏释放资源，保留 unknown 业务诊断；reused／创建不明仍 HOLD，不证明所有后代停止。ACPX 准备失败本候选未增加自动关闭／释放，仍通过显式严格 release_only 恢复，严格证明不可得时再显式 abandon。

当前真实授权调用者可针对精确旧任务显式 `release_only`，不伪造身份、不转移 owner/controller、不派发业务：同 profile 的当前 Hermes 宿主可跨旧 route/session 或本地 standalone/OMP 来源释放；设备本地 CLI capability 或真实 OMP 宿主 capability 可释放旧任务。审计实际 actor，原始来源和 controller 不变。严格路径仅适用于已结算非 native、本地 exact record：持久 SQL fence 阻止迟到写入，至多一次外部 close，严格核验 closed-record/request/no-session；已有不确定尝试只 probe，失败保持 HOLD，不自动降级。**本版本源码；不自动释放既有任务锁**：恢复卡片与严格 `release_only` 共用同一非活跃与失终态结算判定——runner 仅在 `runner_pid` 缺失/整 `0` 或 `os.kill(pid, 0)` 抛出 `ProcessLookupError` 时判为非活跃（活跃/畸形/布尔/负数/`PermissionError` 或不可核验/复用 PID 仍 HOLD，死 PID 本身不证明后端已结算）；已结算 `unknown` 须同时满足 runner 非活跃及匹配 `turn`/`backend_request_id`/`launch_id` 的 `turn_settlement.protocol_settled=True`（畸形或未结算对象不回退旧推断），或本地非 native ACPX exact record 上 `turn_settlement is None` 且整 `exit_code == 0`、`stop_reason in {'end_turn', 'cancelled'}`、已存 `backend_request_id == '<task_id>:<turn>'`（不伪造缺失字段）。满足该共用判据且既有 probe-only fence 尚无 `close` 尝试时，严格 `release_only` 允许执行至多一次严格外部 `close` 并校验 `closed`/request/`no-session` 读回，回执保留 `business_state='unknown'`；后续重试仍仅 probe。

native、无记录、远端或严格证明不可得／不确定时，未显式选择 abandonment 的 `release_only` 保持 HOLD 并给出明确指引，不自动退化为风险释放。只有调用者显式传入 `abandon: true`（CLI `--abandon`）接受风险才执行无证明的资源释放；receipt 标记 `operation: explicit-abandonment` 和可能仍活动风险，不声称 backend 已关闭。公开 receipt 区分 `resource_state`、`business_state`、`risk`、`operation`，明确不证明任意 detached descendants 全停；释放不是业务成功或安全工作区证明。SQL fence 不是操作系统沙箱。已释放重复返回 receipt；不自动重放业务或不确定 close。

严格路径使用与 local start/续轮及 close/reconcile 相同的已配置 `local_toolchain_bin` 子进程链；显式 abandonment 不调用 backend，不需要该链。配置的 Node/npm/ACPX 不齐时严格路径拒绝，不回退 bundled；未配置及远端默认不变。源码候选（本版本源码；不自动释放既有任务锁）不代表部署或真实宿主验收。

## 资源恢复与诊断只读快照（本版本源码）

Hermes、OMP 与 CLI `recovery_status(task_id)` 仅接受精确 task_id（按原始字面精确匹配与回显，不做 trim/归一化），复用 `release_only` 的当前受信宿主准入（本地 `cli`/`source` 标签与模型传入 `user_id`/`task_id` 均不构成跨路线授权，OMP 未绑定首次只读观察复用只读宿主准入且不触发持久 `bind`），不要求旧 route/owner 可用。在严格字段级类型校验与真实闭集投影的 `resource_recovery`（`task_id`: literal `str|None`、`turn`: 正整数 `int|None`、`business_state`/`resource_state`: 合法状态闭集枚举或 `unknown`、`write`: `bool`、`receipt`: `None` 或仅含闭集 `state`/`operation`/`business_state`/`external_close_attempted` 标量的 4 键字典；未知字段/嵌套对象/任意文本一律降级为 `unknown`/`None`，同时兼容正常历史 receipt）之外仅附带审计过的闭集 `diagnostic` 投影（`agent`、`agy_mode`、`native_phase`、`stop_reason`、`exit_code`、`pending_question_count`、`intervention_status` 与安全 `native_diagnostic` 枚举/整数/布尔字段）；严禁跨路线批量 `list`，严禁放行自由文本（`stage`/`tool` 名称与 ID/`settlement_note`/`error`/`prompt`/`question`/`answer`）、`cwd`、`runtime_links` 或 `origin`/`controller` 会话标识。业务 `status`/`events`/控制权限不变。

同一 SQLite 只读事务读取 task 与 release fence；不建目录、初始化 schema、chmod、登记 fence、推进 intervention 或访问执行后端。缺记录/数据库拒绝，不补造 turn。调用者从此投影取得 observed turn 后沿原 release_only 显式恢复，turn 已变化则仍拒绝；释放后用同一只读入口读回。严格关闭回执的 released 与原 business_state 分开显示，资源释放不证明业务成功或全部后代停止。

## P2 fixed-target release-only candidate

One fixed legacy cross-owner task may be finalized by an operator admitted through the existing Hermes sensitive HTTP gate. Exact identifiers belong only in a local untracked policy file, never the public source. This does not transfer the original owner, permit business continuation, or authenticate a submission string. Bind task, owner, turn, backend record, ACP session, profile home and an expiring one-use confirmation to a host-admitted locked snapshot. Preserve business results and completed command history. A durable fence rejects late events, launches, metadata changes and reopen attempts, including writes from previously loaded code. Revoke only unconsumed commands. Release requires a supported exact-record execution-side close, strict matching close receipt, closed-record readback and associated strict no-session result; missing or uncertain evidence retains an unknown reservation without automatic close replay. Offline source/integration verification is not production authorization, deployment or release.

Revision tracking is restricted to exact targets enrolled by prepare; unrelated task create/update/delete must not add auxiliary records or counter writes. Constructor binding and receipt GET must not initialize schema or take a write lock. Receipt uses a read-only database connection and explicitly reports not prepared before initialization. Prepare alone initializes necessary release schema, and target enrollment plus snapshot/nonce binding share one writer transaction so concurrent prepare and update/delete-recreate ABA cannot create an untracked interval.
