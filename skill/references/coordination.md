# 协作判断、反馈与恢复

用于复杂分工、返工、迟到通知、失败恢复及阶段复盘；常规循环留在正文。

## 单一 owner 与有效上下文

独立任务可并行，同一写面只留一个 writer。只读意图、批准策略与写资源占用分别说明，不因 approve-all 就虚构沙箱，也不把所有只读任务串行化。已有平台编排的工作交回其 owner。

父级按原派工通道的精确句柄核对状态，不另派代理查另一代理的私有任务。独审等 writer 权威终态和停写确认后再派独立实例，提供完整句柄、冻结范围与必要脱敏证据；不让审查者等待尚未完成的写入或猜短 ID。同一冻结版本复用一个复核结果，具体新改动／失败才重审。

执行者报告材料缺失或能力不可用，先核准确路径与已有证据；需要纠正时传入实际执行上下文并确认消费，不能只在用户会话里答应。父方并发更新需求时说明准确路径与差异，保留旧基线；已知修订合并到最新文本，不当漂移回退。意外未知写者先停写定位。替换 writer 要有停写证据，超时或沉默不等于退出。

## 连续完成而非局部通过

任务包明确目标、范围、产物、验收和停止条件；返工只列具体缺陷与直接受影响路径，不变成泛化框架。总计划保留所有授权剩余工作，当前状态摘要持续更新，不只在末尾追加成功日志。分别列源码、离线检查、真实执行、部署／加载、文档与用户投递，未完成就称阶段交接，不拿测试数代替完成比例。

用户催收尾不等于取消剩余实现；常规返工在原权限内继续，真正缺决定才提问。只剩简短归整时由 owner 做，不再套规划／写作／独审循环。相同版本复用有效证据，原始反例与直接受影响正常路径优先。只把可复现缺陷或合同违反列必须修复；已知能力限制不自动授权扩建。输入兼容问题要区分缺字段与 null、旧 producer 的待消费任务和真实新增输入，不为单个版本差异造迁移平台。

## 不确定结果与资源压力

断线、interrupted、空摘要或超时，先按精确任务查事件时间线、已落盘产物和清理回执；失败终态不证明没执行，部分文件也不证明完成。保全成果，只续办未完成步骤；认证失败不循环重试。unknown 禁止自动重放，先核原生会话与自有进程，alive 不等于停写。手动原生续轮不会自动修正旧任务登记，不能绕过原占用再建竞争 writer。

主机卡顿／资源耗尽或控制命令连续超时，暂停新派工及自动重试，用现有诊断方法轻量只读取样；涉及多设备分别检查。按创建时间、父子关系、cwd 和精确任务标记确认归属，同名进程或时间重叠不是冲突根因。仅停止获准的自有异常进程，读回消失与资源恢复；缓解压力不等于业务完成。

## 阶段反馈与技能演进

有实质交付的阶段记录原需求、产物／证据、协作问题、原因边界与下一动作，先定位目标项目的维护记录及 GitHub issue，读正文／评论去重。已有入口优先更新，业务问题归业务项目，call-cli 自身问题才归工具项目；不按调用次数建卡。有外部写授权才提交，无授权交草稿和准确目标。写后读回 URL／ID 与正文，不自动关闭尚未验收的 tracked work。

公开材料仅留脱敏机制、最小复现与验收边界；不含原始会话、凭据、私有路径、任务身份或内部库存。根因未知就写待查。一次合成通过或提示词去噪不证明真实平台投递修复。

经核验的非例行教训可修正本技能对应主题：先看是否检索失败、指导矛盾、执行疏漏或运行时缺口；修拥有该问题的规则或提出候选，不不断堆禁令。只读任务不因此取得持久写权；实际改动在现有记录留短说明，后续反例可收窄或撤回。不得新增采集服务或另一份任务状态库。
